## Caveat on precision

These filter by company **name**, not company id, so a common name returns noise.
The precise form uses `currentCompany=["<id>"]`. Scout already receives that id in
the Voyager response — `companyUrn`, e.g. `urn:li:fs_normalized_company:26030483` —
but `scrape_prompt.md` reads only `.name` from that entity and discards the urn.
Capturing it is a one-line change to the scrape, after which these links become exact.
That is worth doing on the next scrape rather than re-running one now.
